# Palantir Foundry 全角色工程与质保协同工作流

本 Skill 提炼并沉淀了硅谷顶级企业服务平台 **Palantir Foundry** 的全套工程研发、前线交付与质量可靠性保证方法论。

在 Palantir 体系中，**不设专职的手工测试岗位**，而是通过 **五大关键角色职责内化 + 强契约工具链** 构筑起“零盲区、零伪交互、不可变交付”的工程质量防线。

## 二、角色专项规范与准入审查表 (Checklists)

### 1. FDSE (Forward Deployed Software Engineer) —— 全栈实现与交互防御

> **角色定位**: “召之即来，来之能战，战之能胜”的前线交付利刃，对所写功能的可用性负最终技术责任。

#### 核心防守职责:
1. **状态机与分段器穷举 (Segment & State Exhaustion)**:
   - 严禁只测“默认状态（Default Tab）”！任何页面若包含 Tab、分段器、折叠面板、下拉筛选，FDSE 必须遍历所有状态分支并验证渲染；
   - 必须测试条件样式分支（如沉浸模式 vs 普通模式、已登录 vs 未登录、空数据 vs 满数据列表）。
2. **零死穴原则 (No Dead Click)**:
   - 页面上凡具备可点击形态的组件（按钮、卡片、胶囊、列表行），底层必须绑定真实的 `onClick` 处理函数或合法的路由 `href`；
   - 禁止留下“看着像按钮，点了毫无反应”的半成品（如空 `onClick` 或只有样式的 `<div>`）。
3. **全局异常与未捕获崩溃拦截**:
   - 严禁在 JSX/TSX 中引用未声明变量（如 `showBanner`）；
   - 所有外部传入的参数、状态必须具备安全兜底与类型保护；
   - 必须通过自动化测试断言 `page.on('pageerror')` 为 0。

#### FDSE 交付前自检清单:
- [ ] 页面内的所有横向 Tab 是否已逐一点击并验证？
- [ ] 页面内所有图标按钮、胶囊筛选是否有真实的点击反馈（触控动效 `active:scale-95`）与业务流转？
- [ ] 关联接口若返回空数组或报错，页面是否有友好的 EmptyState / ErrorState，绝不发生白屏崩溃？
- [ ] 本地修改的全部 TSX/TS 文件已通过增量 `tsc` 检查，0 类型报错？

### 2. DS (Deployment Strategist) —— 业务验收与死穴探路

> **角色定位**: 站在终端用户、商户与监管三方的视角，扮演最挑剔的业务主审官。

#### 核心防守职责:
1. **真实用户旅程探路 (Journey Probing)**:
   - 从用户进入首页、搜索检索、下钻详情、发起预约/购买、支付核销到个人中心查验，走完全闭环路径；
   - 重点审查“下一步应该去哪”的引导链路（如在商品详情看完后能否找到店铺、在个人中心能否直达会员中心）。
2. **业务语义合理性审查**:
   - 严禁履约方式混淆（如民宿套房出现“包邮快递收货地址”、实物商品出现“到店扫码核销”）；
   - 严禁伪造假数据或出现装饰性数字（如假评分、无法解释的统计数字）；
   - 检查分类与字典展示名是否为规范中文（禁止暴露英文枚举大写）。

#### DS 验收核查清单:
- [ ] 核心正向业务流（如预订、下单、认养、报名）能否 100% 跑通到终态？
- [ ] 个人中心所有资产、足迹、权益数字是否真实反映当前账号状态？
- [ ] 逆向业务流（如退款、取消、售后、违规驳回）是否能够安全闭环？
- [ ] 移动端是否具有流畅的滑动、无遮挡视觉、防误触间距？

---

### 3. Core SWE (Platform Software Engineer) —— 编译守卫与平台契约

> **角色定位**: 架构底座守护者，用工具链与静态规则让开发者“想犯低级错误都通不过提交”。

#### 核心防守职责:
1. **增量编译与类型守卫**:
   - 建立增量 TypeScript 检查机制，对变更文件实行 `tsc --noEmit` 0 报错一票否决；
   - 杜绝隐式 `any` 与未声明全局变量的穿透。
2. **模块边界与门面隔离 (Module Boundaries)**:
   - 严格执行 `modules-first` 架构，跨模块调用必须经由 `@/modules/<domain>/public/*` 门面；
   - 严禁在页面路由（`src/app/**`）中直接侵入业务私有实现或绕过 Service 写数据库。
3. **统一 API 契约与解包守卫**:
   - 统一 API 返回形状 `{ success: true, data: <T> }`，前端客户端统一解包；
   - 严禁返回裸 JSON 或散放数据，防止前端 `api.get()` 取数异常抛出 `undefined`。

#### Core SWE 守卫清单:
- [ ] `npm run check:module-boundaries` 静态边界检查 100% 通过？
- [ ] 变动的核心代码是否存在向公共包（shared）反向倾倒业务状态的违规依赖？
- [ ] API 路由层代码行数是否 $\le 40$ 行，严格作为参数编排与 Controller 薄层？

---

### 4. PRE / SRE (Product Reliability Engineer) —— 环境对齐与发布治理

> **角色定位**: 生产与测试环境的看门人，确保运行态（Runtime）与代码态（VCS）100% 精确对齐。

#### 核心防守职责:
1. **环境版本指纹握手协议 (Environment Provenance Handshake)**:
   - 严禁在“未知版本状态”的环境上执行验收测试；
   - 每次测试执行前，探针必须提取靶机 `/api/health` 或静态构建 Hash，比对是否与本地目标 Git Commit SHA 严格一致；
   - 一旦发现远端环境存在版本滞后或镜像未更新，测试立即挂起并发出预警（`ENV_DRIFT_DETECTED`）。
2. **不可变构建与参数注入安全**:
   - 严格执行测试环境发布 SOP（`docs/operations/deploy.md`）；
   - 构建镜像必须加 `--no-cache`，确保 `NEXT_PUBLIC_API_ENCRYPTION_KEY` 等关键环境变量 100% 注入成功；
   - 部署必须使用不可变 tag（如 `rYYYYMMDD-NN`），保留回滚指针。

#### PRE 发布核查清单:
- [ ] 测试环境当前运行容器的镜像 Hash 是否对应最新的 master 提交？
- [ ] 容器状态是否健康（`docker ps` 状态为 `Up` 且已通过健康探针）？
- [ ] 部署后是否自动触发基础 HTTP 200 探活与 API 连通性测试？

---

### 5. FDA (Forward Deployed Architect) —— 数据模型与权限边界

> **角色定位**: 系统顶层架构与数据本体（Ontology）的总设计师。

#### 核心防守职责:
1. **多租户与组织数据作用域 (Data Scope)**:
   - 严格审查 Service 层的 `getDataScope` 与 `buildWhere(scope)`，确保商户端绝对无法跨租户越权查询，管理端严格按行政区划编码（`code LIKE 'SD-JN-%'`）过滤；
   - 客户端上传的 `tenantId` 严禁信任，一律从服务端会话上下文提取。
2. **强一致性与事务边界**:
   - 资金、订单、库存、退款必须在数据库事务（`prisma.$transaction`）内执行原子扣减；
   - 履约与评价状态机严禁产生逆流或非法跳步。

## 三、全角色自动化测试矩阵与执行指引

在执行任何功能开发、缺陷修复或上线验收时，必须按照 Palantir 角色矩阵执行交叉审查：

```bash
# 1. [Core SWE 视角] 模块边界与静态类型自检
npm run check:module-boundaries
npx tsc --noEmit --project tsconfig.json  # 检查目标变更文件

# 2. [FDSE 视角] 毫秒级内存沙箱与定向单测回归
npm run test:pglite <path/to/test-file.test.ts>

# 3. [DS + FDSE 视角] 真实移动端视口 E2E 深度交互与全 Tab 遍历
npx playwright test e2e/... # 或执行专用交互脚本

# 4. [PRE 视角] 靶机版本一致性校验与部署验证
# 执行环境握手：确认目标 IP 响应的 Release SHA 与当前 master 一致
```

## 四、不可逾越的六大交付红线 (Zero Tolerance Rules)

1. ❌ **严禁测试“仅截图不点击”**：快照通过不等于交互可用，必须触发真实点击并验证状态流转。
2. ❌ **严禁“只测默认 Tab”**：同级横向 Tab 必须 100% 全量遍历。
3. ❌ **严禁提交存在未声明变量的代码**：变更文件必须通过 TypeScript 静态编译。
4. ❌ **严禁在未对齐版本的测试环境上出具验收结论**：环境落后必须先部署后测试。
5. ❌ **严禁发布无点击响应的假按钮**：页面所有交互形态元素必须有业务落地。
6. ❌ **严禁忽略控制台未捕获异常**：测试过程中产生的任何 `ReferenceError`/`TypeError` 均视为严重缺陷，用例必须直接红灯失败。
