# E2E 容器沙箱代理网络治理与宿主机私网直连工作流

本 Skill 沉淀了在带有全局透明代理（Mihomo TUN 模式）的 Docker 隔离开发/测试沙箱中，保证**外网 AI 研发服务高可用**与**内网开发机/测试机双向直连互通**的网络运维标准规范。

---

## 一、核心网络拓扑与痛点原理

在具备自动化测试能力的沙箱容器中，网络环境通常具有以下特征：

```
[容器内应用 / curl / Playwright / agy]
                 │
                 ▼
        [127.0.0.1:53 (Mihomo DNS)]
                 │
                 ▼
        [clash0 (TUN 虚拟网卡)]
                 │
        ┌────────┴─────────────────────────────────────────┐
        │ 路由分流规则 (Mihomo Rules)                       │
        ├──────────────────────────┬───────────────────────┤
        ▼ (命中 DIRECT 规则)        ▼ (未命中 DIRECT，走 MATCH)
  [宿主机 / 开发机 / 内网]          [海外代理提供商 (sub.yaml)]
  - 宿主机网关 (172.21.0.1)        - 允许: 美 / 日 / 智 / 新 / 台
  - 开发机 (100.101.22.109)        - 严禁: 香港 / 澳门 (AI 锁区)
  - 测试机 (192.144.253.205)               │
        │                                  ▼
        ▼ (宿主机物理网络直通)       [Google / Gemini / Claude API]
```

### 痛点 1：盲目重启进程导致断网（死穴）
- **错误做法**：执行 `pkill -f mihomo && mihomo ...`。
- **后果**：Mihomo 进程被杀死后，TUN 网卡 `clash0` 与容器 DNS 路由表被破坏，再次拉起需经历订阅重新拉取与测速，在初始化完成前所有外网连接全面报错 `HTTP 000`，只剩下直连内核路由能通。
- **强制红线**：**严禁通过杀进程方式刷新代理配置！** 必须且只能调用 Mihomo RESTful API（`PUT 127.0.0.1:9090/configs?force=true`）实现**零丢包热重载**。

### 痛点 2：自动切到香港节点导致 AI 锁区
- **原理**：香港节点距离大陆近，延迟极低（15~30ms），若未在代理组（`url-test`）中严厉排除，测速机制将 100% 自动切向香港。
- **后果**：Google Gemini、Google AI Studio、Claude 等服务在香港严格锁区，报错 `User location is not supported`。
- **合规名单**：
  - **允许列表**：`.*(日本|美国|智利|新加坡|台湾).*`（均官方支持 Gemini/Claude，台湾兼具 40ms 超低延迟）
  - **排除列表**：`.*(香港|HK|Hong Kong|澳门).*`

### 痛点 3：无法访问宿主机与开发测试机
- **原理**：容器内访问宿主机服务（如 Next.js 开发服务、商户后台）若未配置 DIRECT 放行，请求会被送往海外代理节点，海外节点无法寻址内网 IP，导致 `Empty reply from server` 或超时。

## 二、宿主机网段自适应识别标准

沙箱脚本必须支持在任意宿主机环境启动时自动识别并直连放行：

1. **宿主机 Docker 网关**：通过 `ip route show default | awk '{print $3}'` 动态提取，自动补全 `/32` 直连规则；
2. **容器与宿主机桥接网段**：`172.16.0.0/12`（覆盖所有标准 Docker 子网）；
3. **Tailscale / CGNAT 虚拟局域网**：`100.64.0.0/10`（覆盖宿主机开发机 IP，如 `100.101.22.109`）；
4. **测试服务器专用网段**：`192.144.0.0/16`（覆盖远程测试机，如 `192.144.253.205`）；
5. **本地环回与标准局域网**：`127.0.0.0/8`、`10.0.0.0/8`（adb/模拟器通信）、`192.168.0.0/16`。

## 三、标准刷新 SOP 与命令

### 1. Claude 命令
在会话中直接运行：
```bash
/proxy-refresh [可选额外CIDR]
```

### 2. 自动化脚本调用
脚本持久化保存在工作区仓库中（重启、重建容器均不丢失）：
```bash
bash scripts/refresh-proxy.sh [可选额外CIDR]
```

### 3. 执行结果健康验收标准（四项全通）
执行刷新后，控制台必须完成以下四步校验闭环：
- [x] **Mihomo API 热重载**：返回 `HTTP 204` 或 `HTTP 200`，TUN 接口 `clash0` 无中断；
- [x] **出海活跃节点**：`ACTIVE_NODE` 属于台湾、日本、美国、智利或新加坡，**绝无香港**；
- [x] **外网连通性**：`curl https://www.google.com/generate_204` 返回 `HTTP 204`；
- [x] **宿主机连通性**：`curl http://<宿主机网关>/` 或 `http://100.101.22.109/` 返回 `HTTP 200`。
